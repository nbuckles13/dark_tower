- **Three tests to run before proposing a shared home** (cited from `proto/dark_tower/internal/v1/internal.proto:913` as living here). **Instrument**: an `ANCHOR (DRY)` fits when N sites must hold ONE value; when N sites each make their OWN decision under one rule the instrument is a guard, because a false SSoT hides the fork. **Reachability**: a helper that cannot import the value it validates against is not a home for it, it is a copy — ask whether the proposed home's crate can depend on the anchor (worked case: `crates/common` has no `media-protocol` dependency and must not gain one). **Collapse**: a shared validator picks ONE policy per input class, so check whether the two callers classify any class differently; if they do, the collapse fails open on exactly that class.

## False Positive Boundaries (deliberate non-collapses, each recorded at its own definition)
- Per-service error mapping; MC vs MH `GcClient`; AC vs GC rate limiting; `common::jwt` vs `common::meeting_token`; AC test `Claims { .. }` literals (the surrounding helper IS extracted -> `crates/ac-service/tests/common/jwt_fixtures.rs`)
- Media wire constants: `AEAD_TAG_BYTES` in `crates/media-protocol/src/frame.rs` is not the at-rest envelope tag in `crates/ac-service/src/crypto/mod.rs`; `MAX_PAYLOAD_BYTES` is not MC/MH `MAX_MESSAGE_SIZE`; Rust<->TypeScript codec duplication is designed in (ADR-0036 §2) and vector-guarded
- Three coincident 32-byte constants: `crates/mc-service/src/media_admission/kek.rs` and `crates/mc-service/src/media_admission/identity_key.rs` (sibling files, the reachable accidental collapse) and `WRAPPED_TRANSMIT_KEY_MATERIAL_BYTES` in `crates/media-protocol/src/frame.rs`
- 16-bit ids are four distinct concepts: MC allocation (`crates/mc-service/src/media_admission/sender_id.rs`), MH validation of untrusted inbound and `SlotId` where zero is valid (`crates/mh-service/src/routing/mod.rs`), and `common::types::{UserId, StreamId}`. **Do not create `common::validate_16bit_id()` or `MAX_16BIT_ID`** — every in-tree occurrence is a prohibition (`proto/dark_tower/internal/v1/internal.proto`, `proto/dark_tower/signaling/v1/signaling.proto`, `crates/mc-service/src/media_signaling/capability.rs`, `crates/mh-service/src/routing/mod.rs`, `crates/mh-service/src/webtransport/connection.rs`) and the instruction to create it recurs. Validation routes through `mh_service::routing::SenderId::from_wire()`
- Boundary tests deliberately restate the bound as a literal (`crates/proto-gen/tests/internal_roundtrip.rs`); production code and proto comments reference the constant. Do not "fix" those literals
- MC and MH sender-binding outcome vocabularies are disjoint by construction, not one vocabulary -> `crates/mc-service/src/media_admission/binding_response.rs` vs `crates/mh-service/src/observability/metrics.rs`; MH's private same-named enum in `crates/mh-service/src/webtransport/connection.rs` is a control-flow result, not a label vocabulary. State the correspondence by naming members, never by restating a count -> `docs/observability/metrics/mc-service.md`
- Two deliberate identity-fixture homes, because ADR-0028 layering forbids sharing -> `crates/mc-test-utils/src/media.rs`, `crates/env-tests/src/fixtures/media.rs`
- SDK: internal-layer errors extend bare `Error`, not `packages/sdk-core/src/errors/SdkError.ts` (the public surface); the egress hop-sequence writer and `packages/sdk-core/src/media/pipeline/hopSequenceMonitor.ts` run in opposite directions; the send-drop vocabulary and `packages/sdk-core/src/media/frame/rejectReason.ts` are two vocabularies by design

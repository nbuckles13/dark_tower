## Planning

### Problem in mechanism-language
Task #14 shipped an event-emitting, framework-agnostic SDK core whose public entry point
is `MeetingSession` (`extends TypedEventEmitter<MeetingSessionEventMap>`, `.on(evt,l)→
unsubscribe`, `.state` getter, `.join()`, `.disconnect()`, static `.configure()`). Task
#15 is the reactivity + manual-driver layer on top:
1. **Adapter (R-28)** — bridge the SDK's *push* event model onto Svelte 5's *pull*
   reactivity: a `.svelte.ts` module of `$state` cells, a pure event→state subscription,
   and a lifecycle-bound helper that unsubscribes on unmount (every `.on()` returns an
   unsubscribe closure; the helper must call all of them via `onDestroy`).
2. **Demo (R-29)** — four Svelte views driving the full happy path. Sign-up/sign-in call
   `AuthApiClient`; create-meeting calls `MeetingApiClient.createMeeting`; join drives
   `MeetingSession.join` and renders the reactive store. Stable `data-testid` +
   `window.__darktower_test__` are the contract surface consumed by test-owned tasks
   #18/#19 — correct/stable here even though nothing in this task exercises them live.
3. **Build/dev wiring (R-30)** — Vite defines (`__DEV_TRUST_FINGERPRINT__`,
   `__E2E_HOOKS__`, `__SDK_VERSION__`), AC/GC dev proxy, cert-fingerprint loader feeding
   MC/MH `serverCertificateHashes` into the SDK's dev-gated `connect`, README to Chrome.
4. **Component tests (R-43)** — introduce Vitest 4 Browser Mode (Chromium) — a new tier
   (sdk-core's `test:component` is a node-env bundle test). ~16 tests: store reactivity +
   four-view rendering vs a mocked `MeetingSession`; no real WebTransport/WebCodecs.

### Key design decisions
- **D1 — `$name` public shape.** Svelte 5 `$state` can't be exported as a bare
  re-assignable binding across modules (breaks reactivity). Idiomatic pattern: a
  `.svelte.ts` `MeetingStore` class with private `$state` cells exposed through getters
  `meetingState`/`participants`/`mediaConnections`/`lastError`. Those getters *are* the
  requirement's `$meetingState`/`$participants`/`$mediaConnections`/`$lastError` (ADR-0028
  §6: adapters convert SDK events to native reactivity).
- **D2 — Bind to a structural type, not the concrete class.** `bindMeetingSession` accepts
  `BoundMeetingSession` (`{ readonly state; on<K>(type,l):()=>void }`), which
  `MeetingSession` satisfies unchanged. Tests inject a lightweight `TypedEventEmitter`
  subclass mock without constructing the heavy real facade.
- **D3 — Three-layer split.** `MeetingStore` (reactive state + mutators) /
  `subscribeSession(store,session):()=>void` (pure wiring, returns aggregate unsubscribe;
  testable with no lifecycle) / `bindMeetingSession(session):MeetingStore` (component-init
  convenience: `onDestroy(subscribeSession(store,session))`). Unmount cleanup exercised by
  a mount/unmount component test.
- **D4 — `window.__darktower_test__`** (gated by `__E2E_HOOKS__`): `{ events[]; on(type,l)
  :()=>void }` with a replay buffer so a late Playwright subscriber still sees an already-
  fired `joined`. Bounded event names + already-public roster fields only — never
  tokens/PII. Attached to `window` only when the define is `true` (tree-shaken in prod).
  Documented in the web-app README as a stable #18/#19 contract.
- **D5 — Transport not proxied; only AC/GC HTTP is.** Browser WebTransport to MC/MH is
  direct (uses `serverCertificateHashes`), can't traverse an HTTP proxy. The fingerprint
  loader feeds MC/MH hashes into a `connect` wrapper: `(url,opts)=>baseConnect(url,{...
  opts, devCertificateHashes})`. Absent/empty `fingerprints.json` → no pinning, logged.
- **D6 — Test-only alias** resolves `@darktower/sdk-core` + `@darktower/sdk-svelte` to
  source (mirrors sdk-core's test-utils alias) with `dependsOn` proto-gen `codegen`. No
  built-`dist` dependency for the test tier.
- **D7 — Deps** (pinned; lockfile authoritative): `svelte@5.56.4` (already present),
  `@sveltejs/vite-plugin-svelte`, `@vitest/browser@4.1.8`, `@vitest/browser-playwright@
  4.1.8`, `playwright` (coordinate w/ infra R-35), `vitest-browser-svelte`; root adds
  `eslint-plugin-svelte`+`globals` (the eslint placeholder reserves this for task #15).
  Regenerates `pnpm-lock.yaml`.

### Nx targets (mirror sdk-core naming so CI R-47 / pipeline pick them up)
- sdk-svelte: `build` (vite lib, dependsOn codegen+^build), `test:component` (vitest
  browser, dependsOn codegen), `lint` (tsc+eslint+prettier+svelte-check).
- web-app: `build` (vite SPA, dependsOn ^build), `dev` (vite, cache:false),
  `test:component` (vitest browser), `lint`. Root `nx run-many -t test:component` → the
  existing ci-client.yml `component` job (Chromium already provisioned, forward-compat).

### data-testid (exact, R-29)

`create-button`, `created-meeting-code`, `meeting-code`, `join-button`, `participant-list`,

### Risks

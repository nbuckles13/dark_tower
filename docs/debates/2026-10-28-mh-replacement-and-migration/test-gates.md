# MH replacement — per-service test gates (test specialist)

Rules for every gate: deadlines read `tokio::time::Instant` and are tested with `start_paused` + `advance` (no wall-clock sleeps). Jitter uses a seedable RNG. Metric gates use ADR-0032 `MetricAssertion`, and "never fires" checks use unobserved semantics, not "the delta is zero". Every negative gate is paired with a positive arm in the same test, so an implementation that does nothing fails it. Env-test ceilings are derived from deployed config, apply only on failure, and are never latency targets (§10).

## MC (Tier 1a pure + Tier 1b paused-time integration, fake MHs + GC mock)
- `assess` table: Healthy⇄Lagging reversible; Lagging held >L (=2N) → Impaired (one-way); no entry for >N → Dead (one-way); the age clock starts at the first confirmed RegisterMeeting (an unconfirmed handler never goes Dead before that); a stale/replayed heartbeat with a lower applied generation is not liveness; client loss reports alone never reach Dead; DRAINING → planned path. gRPC channel events are not an input.
- Apply-failure negative gate carried over from §10: inject an MH apply failure; the applied generation does not advance, and Lagging → Impaired.
- Stranded A/B: set {H1(,H2)}, A and B only on H1. H1 stops beating; the GC mock grants H3. Assert H3's RegisterMeeting precedes the client MediaHandlerSet. After A and B send Connected on H3, H3's snapshot carries the A↔B edges and neither is reported unreachable to the other. Assert on snapshots, not internals.
- Two-handler variant: GC mock returns UNAVAILABLE; survivors re-place without GC.
- Per GC outcome: OK → migrate. RESOURCE_EXHAUSTED or UNAVAILABLE with survivors → stay on survivors, back off (config), counted. The same with no survivors → awaiting-handler state, counted and alerting, and a later grant completes recovery. FAILED_PRECONDITION → no retry, loud. A bounded migration-attempt rate when the replacement is also bad.
- Binding gate: `(X, conn)` keys survive Lagging, Impaired and Draining. They are released only after X leaves the set AND MediaHandlerSet has been sent. A Connected from an out-of-set or tombstoned handler → sender 0 AND the ledger is unchanged (record-after-membership reorder in `actors/meeting.rs`). A zombie's Disconnecteds after removal → HandlerNotInSet (counted), and the replacement's connectivity is untouched.
- Verdicts (R4-4, L4-6, L4-7): the heartbeat goes to the MC meeting actor, and the verdict comes from that actor's state. In set (including Registering) → OWNED. Removed → RELEASED(its removal trigger). No actor for the meeting → RELEASED(MEETING_ENDED). Never in the set → RELEASED(UNSPECIFIED), counted. A heartbeat whose mc_id isn't this MC's → FAILED_PRECONDITION, never RELEASED. All arms in one test. Race gate: the replacement Y's first heartbeat, arriving before MC has processed Y's RegisterMeeting ack, is OWNED (Y enters MC's set as Registering before RegisterMeeting is sent). EndMeeting is best-effort: if the fake MH fails EndMeeting, removal still completes with no retry loop, and that MH's next heartbeat gets RELEASED.
- Reconcile (remove-only, previous-heartbeat rule): a key recorded after the previous heartbeat's receipt and absent from the current heartbeat is kept; a key recorded before it and absent is retired.
- Planned ordering: add Y → clients connected to Y → set without X sent → pusher drain → EndMeeting(X). Removal at deadline − margin (the deadline comes from the draining heartbeat) is counted as shed.
- Loss metric (from one snapshot at the Dead/Impaired transition): k of n injected → count + ratio delta; only the latest status per ref counts (a CONNECTED after redial supersedes); a report after removal is ignored; positive arm: an unsuperseded DISCONNECTED is counted. Two set members sharing a URL are attributed by handler_ref. A PLANNED_TRANSFER produces no observation (unobserved).
- media_dial (R4-3, L4-1..L4-4): Ed25519 keypair per meeting; only the public key is on RegisterMeetingRequest.media_dial_public_key (assert it isn't in logs or Debug output, and isn't in AC's JWKS). Register before token (L4-2): no MediaHandlerSet (including the first JoinResponse, which may be empty) names a handler before its RegisterMeeting ack. Every set carries a token for every member: compact JWS EdDSA {token_type=media_dial, sub = the session's own (distinguishing input: another roster member's sub), meeting_id, aud=handler_id, iat, exp=iat+TTL}. Refresh at TTL/3 (jittered, seeded RNG), derived from MC_MEDIA_DIAL_TOKEN_TTL_SECONDS (startup rejects values outside [60, 900]). With paused time across several TTLs, an in-set client never holds only an expired token. A token-only refresh keeps handler_set_version, which advances only on membership change. A FAILED report triggers a fast re-push to that sender only, with no routing effect. A left participant's Connected → sender 0, nothing recorded. MC join and GC reject an MC-minted media_dial; the positive arm is that an AC token is accepted.
- (Round 3: the MC shared-URL add-assertion is dropped. Address uniqueness is a platform invariant, checked by the env-test below.)
- Config: N=0 rejected; interval = N/3 is sent in RegisterMeeting (per meeting, R4-1).

## MH (Tier 1b rigs, paused time)
- Per-meeting heartbeat (R4-1): each registered meeting heartbeats to its own MC independently, carrying the registered mc_id. With paused time, a hung RPC for M1 does not delay M2's tick. applied_generation comes from the routing snapshot (a full config-apply mailbox shows lag); a wedged lifecycle mailbox → no heartbeat; the connected set excludes pre-binding sessions; the connected set reflects a disconnect whose notify exhausted MAX_RETRY_ATTEMPTS. An error verdict (e.g. FAILED_PRECONDITION for the wrong MC) → MH takes no action, and the meeting is still held.
- All-or-none apply (R4-2), parameterised over INVALID / TRANSPORT_INCONSISTENT / STREAM_CEILING / EDGE_CAP: generation 4 is applied and forwarding A→B. Generation 5 carries one valid change plus one refusing change. Asserted on frames through the transport shim: the valid change does NOT take effect, and A→B keeps forwarding. The heartbeat reports applied_generation=4 with apply_refusal=<kind>. Generation 6 (valid) applies and clears the refusal. Extra arm: a FIRST-ever apply refused → heartbeats still flow (they start at registration, not first apply), with applied_generation=0 and apply_refusal set.
- No retries; the per-attempt timeout is below the interval; a hung MC call does not delay the next tick.
- Verdicts: RELEASED(cause) → the meeting ends, active sessions close, no Disconnected is sent; OWNED → nothing; an error → nothing. All arms in one test.
- Pending connections (L4-2, L4-8): the pending-before-registration path is deleted, so a dial carrying a correctly signed token for a meeting MH doesn't hold (never registered, or already released) is DECLINED at accept with nothing parked, because MH has no key for it. Concurrent pending connections per (meeting, sub) are capped at the configured value: the cap+1-th is declined, and the cap-th is admitted. A left participant holding a still-valid token: MC answers sender 0, MH closes with DECLINED, and no frame reaches the connection while it is pending.
- Structural load report immediately after every successful register (t=0, paused time); DRAINING report on SIGTERM.
- Drain: no exit while holding a meeting before the deadline; exit at the deadline with shed counted; early exit when the last meeting is released. The deadline is derived from MH_TERMINATION_GRACE_SECONDS − margin.
- media_dial (L4-1, L4-4, L4-5): MH verifies the EdDSA JWS against that meeting's RegisterMeeting public key. Rejects: another meeting's key (cross-meeting), an expired token beyond the configured skew (the skew is config, about 30 s, no longer the hardcoded 300 s), a token_type other than media_dial, and an AC-signed meeting token. aud ≠ own handler_id → WRONG_HANDLER, reported only after full validation (distinguishing input: a bad-signature token with a wrong aud gets DECLINED, not WRONG_HANDLER). The same token is accepted for repeated dials within its TTL (no jti cache). A migration where the join-time JWT has expired succeeds.
- (R4-1: the decode-limit boot validation is deleted on MC and MH.)

## GC
- AcquireMediaHandler table: {A,B,C} excluding {A,B} → C; excluding all → RESOURCE_EXHAUSTED; one exclude list (current ∪ removed ∪ refused-at-admission) excluded by id, unknown ids ignored (ADR-0039 §3); a caller that is not the meeting's MC → FAILED_PRECONDITION; a draining MH is never granted; the length cap on the exclude sum holds.
- The eligibility/exclusion predicate in Rust, plus a `#[sqlx::test]` proving the SQL matches it. The shared selection function enforces the same invariant at initial assignment.
- MC declares X failed while GC sees X healthy → the grant is still issued, gc_view=healthy label. GC rejects an MC-signed media_dial token (key outside AC's JWKS, and HS256); the positive arm is that an AC token is accepted. L4-9: gc_mh_replacement_requests_total{trigger,outcome,gc_view} rises per report with no handler_id label, and the `gc.mh.replacement_report` INFO event carries the ids. With a seeded RNG, selection is identical with and without reports (evidence only).
- Metric integration tests per ADR-0032.

## Protocol
- Roundtrip tests for every new message (`internal_roundtrip.rs`, `signaling_roundtrip.rs`). ServingState UNSPECIFIED is rejected. A SendTarget/StreamAssignment ref not in the current set is counted and ignored. `verify-codegen.sh` absence checks: process_start_epoch_ms, connection_id legacy-empty, SendTarget/StreamAssignment.media_handler_url, JoinResponse.media_servers, MhConnectionStatus.mh_url.

## Client (unit, MockWebTransport, injected clock)
- applyHandlerSet diff: an add dials through the same code as join; a removal closes a transport the server left OPEN (data-plane fence), removes the egress lane, ends read loops without a transportFault, and sends no DISCONNECTED loss report; a server close right after a set that removed that handler → no loss report.
- Remove ref 1 + add ref 2 with an IDENTICAL URL → a real close+open (not deduped).
- A slot's decoder and replay window survive a set diff; no SessionMedia/TransmitKeyManager rebuild; key id strictly increases across a swap after generation 0.
- media_dial (L4-3, L4-4): the diff keys on handler_ref only, and a token-only refresh (same refs and URLs, new tokens) causes NO close/open (distinguishing). The client keeps the latest token per in-set ref (scoped R-23) and reuses it for redials. The token is opaque, never parsed. After DECLINED for a ref, the client makes no dial until a set carrying a newer token for that ref arrives, then exactly one dial (injected clock). A refresh arriving while the ref is parked releases it and dials.
- Close codes: WRONG_HANDLER, BINDING_CONFLICT and MC_UNAVAILABLE → counted, no loss report, backoff redial while the ref is in the set; HANDLER_RELEASED → expected, no report if the ref has left the set, otherwise grace then DISCONNECTED + redial; DECLINED → token dead, not handler dead: park the ref, report FAILED, exactly one dial when a set with a newer token arrives (ADR-0039 §5); no code → loss report + redial.
- The loss report echoes handler_ref + handler_set_version.
- Join with an empty handler set (L4-2) followed by a set naming a handler → normal media; past the configured bound with no handler, exactly one notice, and the session is kept.

## Env-tests (Layer 7, `crates/env-tests/tests/40_resilience.rs`, feature `resilience`)

- Planned drain: graceful delete. GC sees Draining; the set goes {X,…} → {…,Y} → {…} in order; old handler's connection count for the meeting reaches 0 only after the new handler has the clients; shed-at-deadline unobserved; no loss-metric observation. (Kind gap resolved: see below.)
- Zombie: `shareProcessNamespace: true` on MH pods (Kind-only overlay per security ruling; see round 3); `kubectl debug --target` as uid 65532 STOPs mh-service. Then clients reach the replacement → CONT → the resumed MH receives RELEASED on its first heartbeat; meeting released, no media to the meeting's clients from it, releases_total{trigger, clients} increments. Step one of the task proves the injector in Kind; if it's impractical, use the documented fallback (zombie covered at Tier 1b only).

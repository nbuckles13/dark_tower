RegisterMH endpoint rules (GC), final wording for RegisterMHRequest field comments + ADR:
0. Allowlist first (config keys injected by deploy render, values derived): webtransport_endpoint: scheme https, GC_MH_WT_ALLOWED_HOSTS (exact hosts or ".suffix"), GC_MH_WT_ALLOWED_PORTS; grpc_endpoint: GC_MH_GRPC_ALLOWED_SCHEMES (grpc today = cleartext h2c, unauthenticated; flips by config only to a TLS scheme when S6 mTLS lands, spelling decided at S6), GC_MH_GRPC_ALLOWED_CIDRS, GC_MH_GRPC_ALLOWED_PORTS. Failure = INVALID_ARGUMENT, outcome=invalid_endpoint.
1. An incarnation's endpoints are FIXED FOR ITS LIFE: an existing handler_id re-registering with either endpoint changed = FAILED_PRECONDITION, outcome=endpoint_changed.
2. No two LIVE incarnations share an endpoint; SEQUENTIAL reuse after an incarnation is gone is permitted (fixed address pools: Kind hostPort slots, prod hostPort 443 per node; the platform lock guarantees no live overlap). Against any other handler_id's row matching either endpoint:
   a. both endpoints match -> SUPERSEDE (in-place container restart): the other row is deleted in the same upsert transaction; outcome=superseded, match=both.
   b. exactly one matches and that row is draining, unhealthy, or stale (heartbeat older than the MH staleness bound) -> SUPERSEDE; outcome=superseded, match=one_sided.
   c. exactly one matches and that row is fresh and pending/healthy/degraded -> REJECT FAILED_PRECONDITION with a distinct message ("address_conflict"); outcome=address_conflict. A live serving MH is never displaced by a one-sided match.
3. Superseded rows affect only new selection; MC never reacts to GC registry rows. A superseded id is never re-granted (per-meeting tombstone + deleted row).
Telemetry: gc_mh_registrations_total{outcome, match} (match only on superseded); gc_mh_load_reports_total{outcome=unknown_handler} (a process whose row is gone is alive) = WARNING on any increase; sustained superseded rate = page (security: ping-pong signature); address_conflict persisting beyond the staleness bound = alert (after the bound, case c becomes case b, so persistence means two configured holders of one address).
Tests: one per arm (0 per zone with cross-zone input, 1, 2a, 2b x {draining, unhealthy, stale}, 2c).

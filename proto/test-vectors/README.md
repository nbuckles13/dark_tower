# `proto/test-vectors/`

Cross-language test vectors that gate the Rust and TypeScript implementations of the ADR-0036 §2
media frame format against each other.

| File | What it is |
|---|---|
| `frame-v2.vectors.json` | **The single source of truth** for the v2 frame format across both codecs. Generated by `crates/media-vector-gen`, then committed. |
| `external/sframe-wg/test-vectors.json` | Verbatim upstream SFrame test vectors, pinned at one commit. |
| `external/sframe-wg/manifest.json` | The **shared** row selector and per-suite expectations, read by both language gates. |
| `external/sframe-wg/PROVENANCE.md` | Source, digest, licence text, and what the external anchor does and does not gate. |

## Why these exist

Without them, the two codecs can disagree on the authenticated byte range, a media handler routes
correctly because it never decrypts, and the receiver's verification fails: **black video, silent
audio, both sides' unit tests green** (ADR-0036 §2).

Vectors are the *cheap, fast* gate, not the only one. End-to-end tests with real browser clients
validate the same agreement against a running system and catch what vectors cannot — that both
implementations are wired into the paths they are supposed to serve. Vectors fail in seconds and
localise the defect; end-to-end tests prove the composition.

## Do not hand-edit `frame-v2.vectors.json`

Regenerate:

```
cargo run -p media-vector-gen --bin generate-frame-vectors
```

`crates/media-vector-gen/tests/vectors_are_current.rs` regenerates in memory and byte-compares, so a
hand edit reds in Layer 4.

## A vector that contradicts a recorded ruling is a defect to escalate, not a precedent

Vectors beat **prose** — a summary can go stale, and this file is what both codecs are checked
against. Vectors do **not** beat a recorded ruling.

The reason is provenance: the framing rows are **generated from the Rust encoder and then frozen**.
So a vector contradicting a ruling means that codec implemented the ruling wrongly and the freeze
captured the error. Conforming the other implementation to it makes both **consistently wrong with
the drift guard green** — strictly worse than a divergence, because a divergence is loud and this is
silent.

**Escalate to** the owners recorded for `crates/media-protocol/**` in
`scripts/guards/simple/cross-boundary-ownership.yaml` — protocol and media-handler — plus security.
Named as a lookup rather than as individuals so it still resolves years from now. Do **not** build
against a contradicting vector in the meantime.

**This bites hardest on the extension grammar.** The associated-data-span rows are anchored
externally against the SFrame specification, so they are a real outside check. The TLV registry is
ours alone: nothing outside this repository says what type `0x01` means or that its accepted set is
`0..=100`. Those rows prove *internal consistency* only, never correctness — worth less than the
externally anchored rows, and not to be read as if they were worth the same.

## Provenance split: which rows are worth what

Deliberate, and the strongest available arrangement against a correlated misreading of RFC 9605.

| Rows | Provenance | Worth |
|---|---|---|
| Key schedule, nonce derivation, AEAD primitive | **External** — sframe-wg vectors at a pinned commit | Real outside check. A shared misreading is caught. |
| AAD span, signed range, detached-tag split | **Ours**, two independent derivations (a Rust generator written from the ADR text, and a TypeScript codec written from the same text without reading it) | Catches divergence between the two, not a shared error. |
| Frame header, relay region, TLV registry | **Ours alone** | Internal consistency only. Nothing outside this repository defines them. |

The external anchor gates **four** things and no more: the HKDF-SHA512 key schedule, the nonce
derivation, the AES-256-GCM primitive, and the 128-bit tag length. It gates **none** of our framing —
our SFrame object layout, our AAD span, our signed range, our detached-tag split, our KEK unwrap, or
the frame header. The upstream rows have no relay region, no signature, no wrap and no extensions.
See `external/sframe-wg/PROVENANCE.md` for the full in/out list. **Do not read across.**

## The Rust reference generator is deliberately non-production, and must not be deleted

`crates/media-vector-gen` performs cryptography that no production Rust component performs: a media
handler is keyless (ADR-0036 §4, §7) and a meeting controller never encrypts. All production media
crypto is TypeScript — and story 1 and story 2 both encrypt *and* decrypt in that same TypeScript, so
a **self-consistent** TypeScript error passes every acceptance criterion and survives until a
non-TypeScript implementation appears.

That generator is the non-TypeScript implementation. Deleting it as dead Rust crypto reds guard check
**g11**, which fails if the crate is missing or absent from the workspace `members` list.

## Current gating state — read `gated_by`, not this paragraph

`frame-v2.vectors.json` carries `gated_by` and `cross_language_property_established` as data, so the
file never claims a green it does not have. At the time of writing `gated_by.typescript` is `false`:
the TypeScript codec lands at story task 15, so the AAD span, the signed range and the detached-tag
split are currently gated by the Rust reference on one side and by **nothing** on the other. The
drift guard prints a non-suppressible `WARN frame-vectors:` banner on every run while that holds, and
hard-fails on any drift between the flags and reality in either direction.
